# pulumi-convex

The Terraform provider [`srs/convex`](https://registry.terraform.io/providers/srs/convex)
as a Pulumi SDK for Node.js, generated by Pulumi's
[any-Terraform-provider bridge](https://www.pulumi.com/registry/packages/terraform-provider/).
Its `convex.EnvironmentVariable` sets one environment variable on a running
Convex deployment, Convex Cloud or self-hosted.

No Pulumi package of `srs/convex` is on npm, and SST's `providers` block takes
packages from npm only, so an SST app imports this one from Git instead:

```json
{ "devDependencies": { "@sst-provider/convex": "github:ReAppIt/pulumi-convex#<commit>" } }
```

```ts
import * as convex from "@sst-provider/convex";

new convex.EnvironmentVariable("SITE_URL", {
  deploymentUrl: "https://example-api.example.com",
  name: "SITE_URL",
  value: "https://example.com",
});
```

The package is named `@sst-provider/convex` because SST's bundler leaves that
scope to Node; under any other name it would be bundled and break. It is not
published to npm. The provider reads `CONVEX_ACCESS_TOKEN` (an admin key, or a
Convex Cloud token) from its environment, so the key stays out of state. At
deploy time the Pulumi engine downloads the `terraform-provider` plugin and
`srs/convex` itself. `@pulumi/pulumi` is pinned to 3.215.0, the version SST
4.17 runs.

## Regenerating for a new `srs/convex` release

With the Pulumi CLI that SST runs:

1. `pulumi package gen-sdk terraform-provider registry.terraform.io/srs/convex <version> --language nodejs --out <dir>`
2. Replace the TypeScript sources (`*.ts`, `config/`, `types/`) with
   `<dir>/nodejs`'s, and copy its `version` and `pulumi` fields into
   `package.json`.
3. `npm install && npm run build`, delete `bin/*.js.map`, and write `name` and
   `version` into `bin/package.json`, which the SDK reads its version from.
